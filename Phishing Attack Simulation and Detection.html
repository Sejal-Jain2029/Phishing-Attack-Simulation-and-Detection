How phishing attacks work

Most attacks combine a believable sender, an emotional trigger, and a link or attachment. These are the main types the project covers.

Email phishing

Mass messages that imitate banks, delivery firms, or internal teams and push the reader to a fake login page.

Spear phishing

Targeted messages that use a person's name, role, or projects to look credible.

Fake websites

Look-alike pages that copy a real brand and capture whatever is typed into them.

Look-alike domains

Addresses that swap or add characters, such as rn for m, or add words like "secure" and "login".

Business email compromise

Requests that pose as an executive or supplier, asking for payments or sensitive data.

Smishing and vishing

The same tricks delivered by text message or phone call.

How the simulation runs

Every campaign is authorized, announced to the right owners, and uses harmless landing pages that never store passwords.

  1. Get approval and set scope

    Agree on the target group, dates, and rules with the organization before anything is sent.

  2. Design the scenarios

    Write test emails at different difficulty levels, such as a shipping notice, a password reset, and a shared document.

  3. Launch the campaign

    Send through a phishing simulation platform with tracking for opens, clicks, and reports.

  4. Teach at the moment of the click

    People who click land on a short page explaining the warning signs they missed.

  5. Analyze and repeat

    Compare results across groups and rounds, then adjust training and detection rules.

How attacks are detected

Detection works in layers. Each one catches what the previous layer missed.

Email filtering

  • SPF, DKIM, and DMARC checks to confirm the sender is genuine
  • Sender and reply-to mismatch detection
  • Keyword and urgency scoring in the subject and body
  • Attachment and link scanning before delivery
  • Quarantine rules for high-risk messages

Fake website detection

  • URL features: length, "@" symbols, raw IP addresses, extra subdomains
  • Look-alike checks against a list of trusted brand domains
  • HTTPS and certificate review (HTTPS alone does not prove safety)
  • Page checks for password forms posting to another domain
  • Machine learning classifier trained on labeled safe and phishing URLs

Python detection sketch

The same rules as the checker, written as a small script. It can feed features into a classifier later.

import re
from urllib.parse import urlparse

TRUSTED = {"paypal.com", "google.com", "microsoft.com"}
BAD_TLDS = {"xyz", "top", "click", "zip"}

def score_url(url):
    host = urlparse(url if "//" in url else "//" + url).hostname or ""
    score, reasons = 0, []
    if re.fullmatch(r"[\d.]+", host):
        score += 3; reasons.append("IP address as host")
    if host.count(".") >= 4:
        score += 2; reasons.append("many subdomains")
    if "@" in url or "-" in host:
        score += 1; reasons.append("@ or hyphen in host")
    if host.rsplit(".", 1)[-1] in BAD_TLDS:
        score += 2; reasons.append("risky TLD")
    for brand in TRUSTED:
        name = brand.split(".")[0]
        if name in host and not host.endswith(brand):
            score += 3; reasons.append("brand name on other domain")
    return score, reasons
